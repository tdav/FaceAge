# Передача работы: обучение модели возраста на видеокарте

Этот файл написан для Claude Code на втором компьютере (с видеокартой NVIDIA). Прочитай его целиком, прежде чем что-либо запускать. Состояние на 2026-11-13.

## 1. Что это за проект

FaceAge — Android-приложение (.NET MAUI), которое по фото лица оценивает возраст. Сейчас в нём стоит модель InsightFace `genderage.onnx` с поправочной таблицей. Задача — переобучить модель на собственных фото заказчика, чтобы ошибка стала меньше. Нужна точность до года, рабочий диапазон 13–50 лет.

Работа разбита на три этапа:

| Этап | Что | Где | Состояние |
|---|---|---|---|
| 1 | Выгрузка лиц из Oracle программой FaceExport | сервер с базой, без Python | программа готова; на настоящей базе её запускает пользователь |
| 2 | **Обучение** (`tools/train`) | **этот компьютер, видеокарта** | код готов, на видеокарте ни разу не запускался |
| 3 | Встраивание `model.onnx` в приложение | компьютер разработчика | не начато, будет отдельный план |

Твоя задача — этап 2. Этапы 1 и 3 не трогай.

## 2. Что должно лежать на этом компьютере

1. **Репозиторий** `https://github.com/tdav/FaceAge` (публичный). Для обучения нужна только папка `tools/train`: `train.py`, `dataset.py`, `models.py`, `requirements.txt`, `README.md`. Она есть в `origin/main`.
2. **`genderage.onnx`** — в git его нет (лицензия). Получить одним из способов:
   - скопировать с первого компьютера файл `src\FaceAge\Resources\Raw\genderage.onnx`;
   - или запустить в корне репозитория `.\fetch-assets.ps1` — он скачивает файл и сверяет SHA-256 (`4FDE69B1…D6652FB`). Скачивание — только с разрешения пользователя.
3. **Папка экспорта** от FaceExport — пользователь приносит её сам (диск, сеть). Внутри:
   - `export.json` — параметры вырезания;
   - `metadata.jsonl` — по строке на фото: `file`, `birth`, `shot`, `sex`, `pred`, необязательное `id`;
   - `progress.jsonl`, `skipped.jsonl` — служебные, для обучения не нужны;
   - `images\<возраст>\<guid>.jpg` — лица 256×256.

Если папки экспорта ещё нет, обучать не на чем: останови работу и скажи об этом пользователю. Проверить установку можно на публичном наборе UTKFace, но только если пользователь сам об этом попросит.

## 3. Что установить

| Что | Версия | Проверка |
|---|---|---|
| Windows | 10 или 11 | — |
| Драйвер NVIDIA | свежий | `nvidia-smi` печатает таблицу с названием карты |
| Python | 3.13 с python.org, с галочкой «Add python.exe to PATH» | `python --version` |
| PyTorch | `torch==2.14.1`, `torchvision==0.29.2`, сборка под CUDA (`cu126` или `cu130`) | `torch.cuda.is_available()` печатает `True` |
| Остальные пакеты | по `tools/train/requirements.txt`, версии не менять | `pip install -r` без ошибок |
| Место на диске | около 10 ГБ плюс размер папки экспорта | — |

CUDA Toolkit и cuDNN отдельно ставить не нужно: они идут внутри сборки PyTorch. .NET, Visual Studio и Android SDK для обучения не нужны.

Версии пакетов в `requirements.txt` выбирались 2026-11-12 и на видеокарте не проверялись. Перед установкой проверь, что нужная сборка существует: страница https://pytorch.org/get-started/previous-versions/ , версия 2.14.1. Если сборки под драйвер этого компьютера нет, не подбирай версии молча — сообщи пользователю.

## 4. Порядок работы

Точные команды и ожидаемый вывод — в `tools/train/README.md`, разделы 3–8. Следуй ему, а не памяти. Кратко:

1. Создать окружение: `python -m venv <папка>\venv`.
2. Поставить PyTorch с адреса `https://download.pytorch.org/whl/cu126` (или `cu130`), затем `pip install -r requirements.txt`.
3. Проверить видеокарту: `python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"`. При `False` дальше не идти.
4. **Короткая проверка** всего пути: `--epochs 1 --limit 600`, для `small` и для `large`. В папке результата должны появиться `model.onnx` и `report.md`.
5. **Полное обучение `small`**, затем **`large`**. По умолчанию 30 эпох, пакет 128.
6. Прочитать `report.md` каждой модели и показать пользователю итог.

Параметры `train.py`: `--data` (папка экспорта), `--model small|large`, `--out`, `--genderage`, `--epochs` (30), `--batch` (128), `--lr`, `--freeze-bn` / `--no-freeze-bn`, `--workers` (4), `--limit`, `--no-pretrained`, `--resume`.

Обучение долгое: запускай его в фоне и не опрашивай каждые несколько секунд.

## 5. Как понять, что получилось

- Главная цифра — `report.md`, таблица «Сводка», строка «обученная», режим **phone**, столбец **MAE** (средняя ошибка в годах).
- Сравнивать со строкой **«исходная с поправкой»** — так приложение работает сейчас. Обученная модель имеет смысл, только если её MAE в режиме `phone` ниже.
- «Расхождение ONNX Runtime с PyTorch» в конце отчёта должно быть меньше 0,01 года. Если больше, `model.onnx` использовать нельзя.
- Цифра в отчёте слегка оптимистична: лучшая эпоха выбирается по тем же отложенным фото, по которым считается отчёт.

## 6. Когда остановиться и спросить пользователя

- `torch.cuda.is_available()` печатает `False`.
- После первой эпохи MAE в режиме `phone` выше 15–20 лет.
- Строка `Сверка pred: … ПРЕВЫШЕН ПОРОГ` с рамкой из восклицательных знаков. Обучение при этом продолжается, но результат может быть негоден: покажи пользователю строку сверки и `export.json`.
- `CUDA out of memory`: начать заново с `--batch 64`, затем `--batch 32`. При `--resume` менять `--batch` нельзя.
- Сообщение «В отложенной части нет фото 13–50 лет».
- Первая загрузка весов для `large` (около 20 МБ из интернета) — это скачивание, на него нужно разрешение.

## 7. Что не проверено

Всё обучение проверялось только на процессоре и на публичном наборе UTKFace. Впервые на этом компьютере запускаются:

- обучение на видеокарте (скорость и расход памяти; смешанной точности в коде нет, обучение идёт в float32);
- модель `large` с настоящими стартовыми весами;
- данные заказчика: распределение возрастов, качество фото, сверка `pred`.

Значения скорости обучения и заморозки BatchNorm подобраны на маленькой модели и UTKFace; различия между вариантами были в пределах шума. Если хочешь менять их — сначала скажи пользователю, зачем.

## 8. Что принести обратно

Из каждой папки результата (`small`, `large`) три файла: `model.onnx`, `report.md`, `report.json`. Файлы `best.pt` и `last.pt` не нужны.

## 9. Жёсткие правила

- **Персональные данные не покидают этот компьютер.** Фото лиц, даты рождения, `metadata.jsonl` и обученные на них модели (`model.onnx`, `*.pt`) нельзя коммитить, пушить и отправлять во внешние сервисы. Репозиторий публичный. Папку экспорта и папку результатов держи **вне** репозитория.
- Коммит и пуш — только по прямой просьбе пользователя. `git add` только по точным путям файлов, без `-A` и `.`.
- Ответы, комментарии в коде и сообщения коммитов — на русском.
- Тесты, тестовые данные и моки не менять, не спросив: «Нужно ли написать/обновить тесты для этого кода?».
- Процессы завершать только по своему PID.
- Пароли и строки подключения не записывать в файлы репозитория, журналы и ответы.
