# Дообучение модели возраста на фото из Oracle — описание проекта

Дата: 2026-11-12. Статус: принято заказчиком («ок, делай»); вопросы без ответа закрыты допущениями (раздел 13).

## 1. Зачем

Приложение FaceAge (Android) определяет возраст по лицу с фронтальной камеры. Сейчас средняя ошибка для 13–40 лет — 5,7 года (замер на UTKFace), подростков модель почти не отличает от взрослых. Это слишком грубо.

У заказчика есть база Oracle с фотографиями стандарта ICAO (один человек — одно фото, высокое качество), датой рождения и датой съёмки. На этих данных нужно обучить модель возраста и вернуть её в FaceAge.

Работа делится на две программы, потому что данные и вычислительная мощность находятся в разных местах:

- на **сервере** с базой есть только процессор, и туда нельзя ставить Python и пакеты;
- на **локальном компьютере** есть видеокарта NVIDIA, туда можно ставить Python.

## 2. Цели, не-цели, анти-цели

**Цели**

- Наименьшая возможная средняя ошибка возраста для людей 13–50 лет в приложении на телефоне.
- Честная цифра точности: замер только на фото, которые модель не видела при обучении.
- Обученная модель подключается к FaceAge с минимальными правками приложения.

**Не-цели**

- Точность «±1 год в среднем». Ни одна опубликованная модель этого не даёт; ожидания — в разделе 9.
- Определение пола, защита от подмены лица (фото вместо человека), возрасты вне 10–55 лет.
- Обучение на сервере и обучение средствами .NET.
- Окно (GUI) у программы обучения.

**Анти-цели — это провал, даже если всё работает**

- Точность, измеренная на тех же фото, на которых модель училась.
- Модель, которая хороша на фото ICAO, но на телефоне хуже нынешней. Старая модель и её поправочная таблица остаются запасным вариантом, пока новая не проверена на живых людях.
- Пароль к базе, сохранённый на диск или попавший в журнал.
- Лица, даты рождения или обученная на них модель, попавшие в публичный репозиторий без решения заказчика.

## 3. Общая схема

```
Сервер (CPU, .NET 10)                 Локальный ПК (NVIDIA, Python)           Телефон
┌──────────────────────┐   папка     ┌───────────────────────────┐  .onnx  ┌─────────┐
│ FaceExport           │ ──────────▶ │ train.py                  │ ──────▶ │ FaceAge │
│ Oracle → лицо 256×256│  экспорта   │ обучение, отчёт, ONNX     │         │         │
└──────────────────────┘             └───────────────────────────┘         └─────────┘
```

1. **FaceExport** — Windows Forms, .NET 10. Читает фото из Oracle, вырезает лица, пишет папку экспорта.
2. **train.py** — скрипт Python + PyTorch. Обучает модели по папке экспорта, пишет `.onnx` и отчёт.
3. **Возврат в FaceAge** — отдельный небольшой этап после того, как заказчик обучит модель (раздел 7). В план этого проекта входит только его описание.

Две программы связывает только формат папки экспорта (раздел 4). Он фиксируется первым, после чего программы делаются параллельно в двух ветках.

## 4. Договор: формат папки экспорта

```
<папка экспорта>\
  export.json          параметры экспорта
  metadata.jsonl       одна строка JSON на каждое сохранённое фото
  progress.jsonl       одна строка JSON на каждую завершённую пару «возраст + пол»
  images\<возраст>\<guid>.jpg
```

**Изображение.** JPEG 256×256, качество 95, цветное. Имя — GUID. Подпапка — полных лет на день съёмки, вычисленных из дат.

**Геометрия кропа.** Та же, что в телефоне (`AgeEstimator.Analyze`): квадрат с центром в центре рамки лица YuNet, повёрнутый на угол линии глаз (roll). Отличий два:

- Сторона квадрата = большая сторона рамки × **1,75** (в телефоне × 1,5). Запас нужен для случайных сдвигов и масштаба при обучении. «Вид телефона» — это центральные 1,5 / 1,75 = 85,7 % кадра (около 219 px).
- За краем фото продолжаются крайние пиксели, а не чёрный цвет, как в телефоне. Фото ICAO кадрировано тесно: квадрат кропа выходит за его края слева, справа и сверху (по прикидке, 10–15 % кадра 256 с каждой стороны и около 5 % внутри «вида телефона»). На телефоне кадр широкий и чёрных полос почти не бывает, поэтому учить модель на полосах нельзя. Фон ICAO однотонный, так что продолжение края выглядит естественно.

Уменьшение исходного фото — с усреднением (без «ступенек»), не точечной выборкой.

**metadata.jsonl** — UTF-8 без BOM, одна строка на фото:

```json
{"file":"27/3f2a9c1e-5b7d-4e0a-9c1f-0d2e8a6b4c11.jpg","birth":"1990-05-17","shot":"2017-08-02","sex":"F","pred":31.4}
```

| Поле | Смысл |
|---|---|
| `file` | путь относительно `images\`, разделитель `/` |
| `birth`, `shot` | дата рождения и дата съёмки, `ГГГГ-ММ-ДД` |
| `sex` | значение параметра `:sex`, с которым получена строка |
| `pred` | возраст, который дала нынешняя модель телефона на этом фото, без поправочной таблицы |

Точный возраст программа обучения считает сама: `(shot − birth) в днях / 365,2425`.

Поле `pred` — проверка договора: программа обучения прогоняет ту же исходную модель через свой препроцессинг и сверяет результат с `pred` по всем отложенным фото.

- Числа не совпадут точно и не должны: телефон берёт 96×96 точечной выборкой из исходного фото и заливает края чёрным, Python работает с уже уменьшенным JPEG. Сравниваются средние: среднее смещение и средняя абсолютная разница.
- Сверка ищет грубые ошибки препроцессинга: перепутанные каналы цвета, не тот масштаб кропа, не та нормализация.
- При превышении порога `train.py` печатает заметное предупреждение и пишет его в отчёт, но обучение не останавливает.
- Пороги задаются по пробному прогону (раздел 10): сверка обязана сработать на двух намеренных поломках (каналы BGR вместо RGB; масштаб 1,75 вместо 1,5) и молчать на правильном препроцессинге.

**export.json** — параметры, по которым сделана папка: версия формата, размер (256), `cropScale` (1,75), `modelCropScale` (1,5), способ заполнения за краем, качество JPEG, имя модели детектора. Программа обучения читает геометрию отсюда, а не из констант.

**progress.jsonl** — `{"age":27,"sex":"F","returned":2007,"saved":2000,"skipped":7}`.

**Порядок записи.** Сначала файл JPEG, потом строка в `metadata.jsonl` со сбросом на диск. Источник истины — `metadata.jsonl`: JPEG без строки игнорируется, оборванная последняя строка отбрасывается.

## 5. Программа 1 — FaceExport

Windows Forms, `net10.0-windows`, каталог `tools/FaceExport`. Собирается автономно (self-contained, win-x64): на сервер копируется папка, ставить ничего не нужно.

**Окно** (макет согласован):

- сервер Oracle (`host:port/service`), пользователь, пароль;
- SQL-запрос — многострочное поле с параметрами `:age` и `:sex`;
- возраст «от» и «до» (по умолчанию 10 и 55), значения `:sex` через `;`;
- папка экспорта и кнопка «Обзор»;
- ход текущей пары и общий, счётчики (сохранено, пропущено, скорость, осталось), журнал по парам;
- кнопки внизу справа: «Стоп», правее — «Старт».

Раскладка (макет показан заказчику в переписке и принят; в репозитории его нет, ориентир — эта схема):

```
┌ FaceExport — экспорт лиц для обучения ─────────────────────┐
│ Сервер Oracle        [ dbhost:1521/ORCL                  ] │
│ Пользователь, пароль [ reader          ] [ ••••••••      ] │
│ SQL-запрос           [ многострочное поле,               ] │
│                      [ моноширинный шрифт, 5 строк       ] │
│ Возраст и пол        от [10] до [55]   значения :sex [M;F] │
│ Папка экспорта       [ D:\FaceExport            ] [Обзор]  │
├────────────────────────────────────────────────────────────┤
│ Возраст 27, пол F: 1 243 из 2 000            пара 35 из 92 │
│ [███████████░░░░░░░░░░░░░░░░░░░]                           │
│ Сохранено 67 243 │ Пропущено 318 │ 14 фото/с │ Ост. 2 ч    │
│ журнал: возраст 26, M: сохранено 2 000, пропущено 4        │
├────────────────────────────────────────────────────────────┤
│                                          [ Стоп ] [ Старт ]│
└────────────────────────────────────────────────────────────┘
```

**SQL.** Задаёт заказчик. Запрос возвращает три поля по позиции: 1 — фото (BLOB), 2 — дата рождения, 3 — дата съёмки. Образец:

```sql
SELECT photo, birth_date, shoot_date
FROM (
  SELECT p.photo, p.birth_date, p.shoot_date
  FROM persons p
  WHERE p.sex = :sex
    AND FLOOR(MONTHS_BETWEEN(p.shoot_date, p.birth_date) / 12) = :age
  ORDER BY DBMS_RANDOM.VALUE
)
WHERE ROWNUM <= 2000
```

**Работа.**

- Программа перебирает возрасты от «от» до «до» и для каждого — значения пола. На каждую пару выполняется один запрос с привязкой параметров по имени.
- Строки читаются и обрабатываются по одной, в одном рабочем потоке; окно при этом не зависает. В памяти одновременно находится одно фото.
- Для каждой строки: открыть фото → найти лицо и угол тем же кодом, что в телефоне (`AgeEstimator`, исходник подключается ссылкой, как в `tools/AgeEval`) → вырезать 256×256 → записать JPEG → дописать строку в `metadata.jsonl`.
- Фото пропускается (и считается в счётчике с причиной), если оно не открывается, лицо не найдено, даты пустые или съёмка раньше рождения. Фильтры качества телефона (резкость, яркость, размер) здесь не применяются: фото студийные.
- Если лиц несколько, берётся лицо с наибольшей уверенностью детектора — как в телефоне.
- Если запрос вернул меньше 2 000 строк, это не ошибка: в журнале видно, сколько получено.

**Остановка и возобновление.**

- «Стоп» дожидается конца текущего фото.
- Завершённая пара записывается в `progress.jsonl` и при следующем запуске пропускается.
- Незавершённая пара при следующем запуске выгружается заново: её строки удаляются из `metadata.jsonl`, её файлы — из `images\`.
- Ошибка Oracle останавливает работу с сообщением; пара не считается завершённой.
- Если в папке уже есть `export.json` с другими параметрами кропа, программа отказывается продолжать и говорит почему.

**Безопасность.**

- Пароль вводится при каждом запуске, живёт только в памяти, не пишется в настройки и журнал.
- Остальные поля программа запоминает между запусками.
- Рекомендуется учётная запись Oracle с правом только на чтение.

## 6. Программа 2 — обучение

Каталог `tools/train`: скрипт(ы) Python, `requirements.txt` с точными версиями, `README.md` с установкой на компьютер с NVIDIA. Запуск из командной строки, прогресс печатается в консоль. Работает без сети после установки пакетов; исключение — первый запуск модели `large`: он скачивает веса основы (около 20 МБ).

```bash
python train.py --data D:\FaceExport --model small --out runs\small
```

**Данные.**

- Читается `metadata.jsonl`; возраст — дробный, из дат.
- 85 % фото — обучение, 15 % — проверка. Деление — по хешу имени файла: оно одинаково при каждом запуске и для обеих моделей.
- Возрасты 10–12 и 51–55 участвуют в обучении, но в итоговой цифре не учитываются (отчёт показывает их отдельно).
- Если в какой-то паре «возраст + пол» фото меньше, чем в остальных, её примеры берутся чаще, чтобы модель не тянуло к частым возрастам.

**Что видит модель.** Центральная область кадра экспорта («вид телефона», 85,7 %), приведённая к размеру входа модели. При обучении — со случайными искажениями, которые приближают студийное фото к селфи: сдвиг, масштаб, поворот до ±12° (детектор в телефоне ошибается в угле примерно на 10°), зеркало, яркость и цвет, размытие, уменьшение с увеличением (лицо в кадре телефона мельче), шум, артефакты JPEG, изредка — чёрная полоса у края (так выглядит в телефоне лицо у границы кадра).

**Две модели.** Обе обучаются и сравниваются на одних и тех же отложенных фото.

| | `small` | `large` |
|---|---|---|
| Основа | нынешняя `genderage.onnx` (InsightFace), переведённая в PyTorch | готовая сеть для телефонов, предобученная на ImageNet |
| Вход | `data` [N,3,96,96], RGB 0…255 | `data` [N,3,224,224], RGB 0…255, нормализация внутри графа |
| Выход | `fc1` [N,3], возраст = `fc1[2] × 100` — как сейчас | `age` [N], возраст в годах |
| Правки в FaceAge | только замена файла и отключение поправочной таблицы | размер входа и имя выхода |
| Лицензия | некоммерческая (InsightFace) | по лицензии основы; годится только основа, разрешающая коммерческое использование |

Критерии выбора основы для `large` (конкретную сеть выбирает исполнитель и проверяет лицензию весов): веса доступны с лицензией, разрешающей коммерческое использование; модель экспортируется в ONNX и запускается в ONNX Runtime 1.31.1; на телефоне пара «кадр + зеркальная копия» считается не дольше примерно 80 мс на двух потоках arm64 (иначе приложение не наберёт 10 кадров за 3 с). Телефона для замера у исполнителя нет, поэтому берётся заведомо лёгкая сеть «телефонного» класса, а время измеряется на этапе 3 на телефоне заказчика.

Для `small`: до начала обучения проверяется, что модель после перевода в PyTorch выдаёт те же числа, что исходный ONNX.

**Результат запуска** в папке `--out`:

- `model.onnx` — лучшая по отложенным фото версия; после записи проверяется, что ONNX Runtime выдаёт те же числа, что PyTorch;
- `report.md` и `report.json` — отчёт;
- контрольная точка для продолжения прерванного обучения.

**Отчёт** — всё по отложенным фото, для возрастов 13–50, с усреднением «кадр + зеркало», как в телефоне:

- средняя ошибка (MAE) общая, по каждому году возраста, по полу;
- среднее смещение (завышает или занижает) по каждому году;
- доля фото с ошибкой не больше 1, 2, 3 и 5 лет;
- те же цифры на «телефонном» варианте отложенных фото — с фиксированными искажениями, одинаковыми при каждом запуске;
- сравнение: исходная модель, исходная модель с поправочной таблицей (как в приложении сейчас), `small`, `large`;
- сверка с полем `pred` (раздел 4).

## 7. Этап 3 — возврат модели в FaceAge (после обучения, отдельный план)

Делается, когда заказчик принесёт `model.onnx` и отчёт. Здесь — только что предстоит:

- положить модель в приложение; для `large` — поправить в `AgeEstimator` размер входа и чтение выхода;
- отключить поправочную таблицу (она подобрана под старую модель);
- заменить на экране фразу о точности цифрой из отчёта;
- измерить время работы модели на реальном телефоне;
- проверить на живых людях с известным возрастом. Только после этого старая модель убирается.

## 8. Окружение и ограничения (проверено 2026-11-12)

- **Компьютер разработки:** .NET SDK 10.0.302 и 11.0.100 (в `global.json` версия SDK не закреплена, сборку ведёт 11.0.100), Windows Desktop Runtime 10.0.15, Python 3.13.7, PyTorch не установлен, видеокарты NVIDIA нет.
- **nuget.org с компьютера разработки недоступен.** Сборка идёт из локального кэша с `-p:RestoreIgnoreFailedSources=true`. В кэше есть: `Oracle.ManagedDataAccess.Core` 23.26.400, `Microsoft.ML.OnnxRuntime` 1.31.1, `Microsoft.Maui.Graphics` (нужен `AgeEstimator`), пакеты среды выполнения `win-x64` для .NET 10 до версии 10.0.14 включительно. Автономная сборка должна использовать версию среды, которая есть в кэше.
- **PyPI доступен.** Последние версии на дату проверки: `torch` 2.15.0, `onnx2torch` 1.5.15, `onnx` 1.23.2, `onnxruntime` 1.31.1, `timm` 1.0.31. Точные версии и сборку PyTorch под видеокарту закрепляет исполнитель после проверки.
- **Сервер:** Windows, только процессор (8 ядер), ставить ничего нельзя.
- **Данные:** возрасты 13–50 (читаем 10–55), по 2 000 мужчин и 2 000 женщин на каждый год — до 184 000 фото, каждое до 1 МБ. Папка экспорта — около 5–6 ГБ (оценка).
- **Персональные данные:** папка экспорта содержит лица и даты рождения. Она не кладётся в репозиторий и никуда не отправляется.
- **Модель на основе этих фото** по умолчанию в публичный репозиторий не коммитится (как сейчас `genderage.onnx`).

## 9. Ожидания по точности (оценка, не обещание)

Оценки — по открытым публикациям на похожих данных (набор MORPH: лучшие большие модели дают 2,0–2,6 года). Настоящие цифры покажет отчёт.

| Модель | Ожидаемая средняя ошибка на фото ICAO, 13–50 лет |
|---|---|
| нынешняя | замерим (на UTKFace было 5,7–8,5) |
| `small` после обучения | 3–4 года |
| `large` | 2–3 года |

На телефоне ошибка будет больше, чем на фото ICAO: камера, свет и ракурс другие. Насколько больше — покажут «телефонный» вариант отчёта и проверка на живых людях.

## 10. Проверка до реальных данных

Вся цепочка проверяется на компьютере разработки без Oracle и без видеокарты, на наборе UTKFace (23 711 фото с известным возрастом). Набор лежит во временной папке сессии и может исчезнуть, поэтому первым шагом плана он копируется в постоянную папку вне репозитория.

1. Код вырезания и записи из FaceExport запускается на файлах UTKFace (например, режимом в `tools/AgeEval`) и создаёт папку экспорта в формате раздела 4. Даты подставляются условные, чтобы возраст совпал с известным.
2. `train.py --model small` учится на части этой папки на процессоре несколько эпох: ошибка на отложенных фото должна стать ниже, чем у исходной модели.
3. Полученный `model.onnx` подставляется вместо `genderage.onnx` в `tools/AgeEval`: модель загружается и даёт осмысленный возраст.
4. Сверка `pred`: молчит на правильном препроцессинге и срабатывает на двух намеренных поломках (раздел 4). По этому прогону задаются её пороги.

Ограничение пробного прогона: фото UTKFace маленькие (200×200) и кадрированы иначе, чем ICAO. Поведение на больших фото и на краях кадра проверяется только на первых реальных данных — первый экспорт на сервере делается на одном возрасте, и заказчик просматривает несколько полученных лиц глазами.

Чтение из Oracle на компьютере разработки не проверяется: доступной базы нет (допущение 4, раздел 13). Обучение на видеокарте проверяет заказчик по `README.md`.

## 11. Риски

| Риск | Что делаем |
|---|---|
| Фото в базе не JPEG (например, JPEG 2000) — стандартные средства Windows его не откроют | вопрос к заказчику; при необходимости — библиотека декодирования |
| Перевод `genderage.onnx` в PyTorch не удастся или даст другие числа | проверка равенства выходов до обучения; запасной путь — собрать ту же сеть вручную по графу |
| Модель учится на студийных фото, а работает на селфи | искажения при обучении, «телефонный» вариант отчёта, проверка на живых людях, старая модель как запасной вариант |
| Кроп в Python не совпадает с кропом телефона | поле `pred` и сверка в отчёте |
| На сервере нет системных библиотек, нужных ONNX Runtime, или версия Windows не подходит .NET 10 | вопрос к заказчику о версии Windows; нужные библиотеки кладутся рядом с программой; первый запуск на сервере — на одном возрасте |
| Драйвер Oracle не соединяется со старой версией базы | вопрос к заказчику о версии Oracle; в кэше есть драйверы 23.x и 3.21.x |
| Каждый запрос просматривает таблицу целиком, экспорт идёт долго | возобновление по парам; заказчик может ускорить свой SQL |
| `large` слишком медленная для телефона | критерий 80 мс при выборе основы, замер на телефоне на этапе 3 |

## 13. Кто что решил

**Решения заказчика**

- Две программы: экспорт на сервере (Windows Forms, .NET 10) и обучение на локальном компьютере с NVIDIA (можно Python).
- SQL возвращает фото, дату рождения, дату съёмки; строки обрабатываются по одной в одном потоке.
- Отдельный запрос на каждый возраст и пол, по 2 000 фото; возрасты 13–50.
- Лицо сохраняется как JPEG 256×256 с именем-GUID; описание — в JSON, запись синхронно с файлом.
- Отдельные ветки.

**Решения автора описания** (можно оспорить)

- Файл описания — JSON Lines, а не один JSON-массив.
- Подпапки по возрасту внутри `images\`.
- Запас кропа 1,75 и «вид телефона» 85,7 % кадра.
- За краем фото — продолжение крайних пикселей, а не чёрный цвет.
- Поле `pred` и сверка по нему: по средним, с предупреждением, без остановки обучения.
- Для `large` — заведомо лёгкая сеть, замер скорости на телефоне заказчика на этапе 3.
- Читать 10–55 лет, считать точность по 13–50.
- Деление 85/15 по хешу имени файла.
- Две модели (`small`, `large`) и их договор входа-выхода.
- Обучение — скрипт командной строки.
- Пароль не сохраняется; обученная модель по умолчанию не коммитится.
- Этап 3 планируется отдельно, когда появится модель.

**Допущения по вопросам, оставшимся без ответа** (каждое можно отменить)

1. **Тесты не пишутся:** явного подтверждения заказчика нет. Проверка — пробным прогоном (раздел 10).
2. **Фото в базе — JPEG** или другой формат, который открывает Windows (PNG, BMP). Фото, которое не открылось, пропускается и считается; если не открывается ни одно, это покажет первый же запуск.
3. **Версии Oracle и Windows на сервере неизвестны.** Драйвер по умолчанию — `Oracle.ManagedDataAccess.Core` 23.26.400; версия задаётся одним свойством сборки, чтобы пересобрать с 3.21.x для старой базы. Требования .NET 10 к Windows записываются в README.
4. **Доступной базы Oracle для проверки нет.** Чтение из Oracle впервые проверяется на сервере заказчика, на одном возрасте.
5. **Компьютер для обучения — Windows с видеокартой NVIDIA и интернетом.** README описывает установку; размер пакета при обучении задаётся параметром.
